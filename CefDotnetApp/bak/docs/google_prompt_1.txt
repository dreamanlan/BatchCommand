## MetaDSL代码

**MetaDSL语法规范**

1. 语句用 `;`（顶层及`{}`参数）或 `,`（其它括号参数）分隔。末参数后右括号/后续操作符可隐式终止，其余须显式分隔。右括号不标记语句结束，其后仍需分隔符。
2. 语句由一或多个函数顺序连接，需消歧时用空格/tab分隔。
3. 函数类似C调用，支持高阶调用。括号：`()`/`[]`/`{}`。函数名与参数表均可省略但不可同时省略；多函数语句仅首个可省名称。
4. 参数即语句，分隔规则同上。末参数后 `,` 通常省略，`;` 通常保留。
5. 支持类C操作符表达式作语法糖（前缀/中缀/三目，省略参数表括号）。
6. 函数名：C标识符规则。变量：`@`=全局，`$`=局部。常量：布尔/整数/浮点/字符串（同JS，单/双引号，路径用`/`或`\`）。变量类型额外支持对象（由解释器解释）。
7. 特殊括号：`{: :}` 原始代码块（单参数，不处理转义）。`@@delimiter(script,"begin","end");` / `@@delimiter(string,"begin","end");` 自定义脚本括号/字符串引号，均原样解释不处理转义。分隔符为普通单词时用换行或空字符与内容分隔。
8. 扩展括号对：`<: :>`、`[: :]`、`<% %>`、`[% %]`、`{% %}`、`<[% %]>`，仅标记不同，无预定义语义。
9. 成员访问语法糖：对象名为函数名，成员为唯一参数。访问符：`.`/`.*`/`->`/`->*`/`::`。通常用`.`，括号用`()`/`[]`/`{}`，其它非必要不用。
10. 注释：`//`（单行）、`/* */`（多行）、`#`（单行）。
11. 控制流：`if`/`elif`(或`elseif`)/`else`、`while` 类C写法（`else if`写作`elif`，非嵌套）。迭代器`$$`是普通变量，循环开始应赋给局部变量防内层覆盖。`loop($ct){...};` 按次数；`looplist($list){...};` 遍历列表；`looplist($ht){$$.Key,$$.Value};` 遍历哈希；`foreachvalue($a,$b,$c){...};` 遍历指定值列表。
12. 函数定义：`script(name)params($p1,$p2){stmts;};`，但metadsl代码块不能包含函数定义，函数定义只用于dsl脚本文件。
13、返回：`return($r);`；单值非表达式可写`return $r;`；操作表达式必须用函数调用样式。
14. `help("关键字");` 获取API帮助。
15. MetaDSL脚本不支持异常处理，没有try-catch-finally这样的语法结构。
16、MetaDSL脚本没有for、foreach语句与switch语句。
17. agent执行的MetaDSL代码整体会包装成一个函数执行，所以代码里不能再包含函数定义（script只用于框架脚本）。
18. 再次强调：metadsl脚本每个语句都要以分号结尾，复合语句也如此。

**MetaDSL使用注意**

1. 一次只发一段代码，用markdown代码块包裹，记得代码块开始与结束标记单独放一行（为保证正确，开始标记前与结束标记后加空行）。
2. 首行必须是 `// @execute` 或 `# @execute` 识别标签，单独占一行。
3. 最后语句返回值即结果，或`return(val)`显式返回；多值用stringbuilder拼接。
4. 如果代码字符串内出现markdown代码块标记，整个代码的markdown代码块标记需要使用不同或更多字符的标记。
5. `list_dirs`/`list_files`等搜索key必须加通配符`*`或`?`，否则要求完全匹配。
6. 字符串/文件内容搜索用正则或子串匹配，不要写成文件通配符。
7. 字符串替换默认非全字匹配，全字匹配指明exactMatch参数为true或用正则API（`regex_replace`/`regex_find_all`）。
8. 数字转字符串用`to_string`或`format`（C#格式化语法，`{}`需写两遍转义）。
9. 使用API前先用`help`查阅。
10. 常用数据结构类api包括：tuple、array、list、hashtable、stack、queue等，使用help查阅后使用。
11. 条件表达式使用`? :`三目运算符，或使用`if_expr(expr,a,b)`。
12. 至关重要：切勿遗漏变量名、路径或公式中的任何下划线（_）。请务必严格保持所有 snake_case 格式。
13. 留意完整报错信息，中间语句报错不一定中断执行。

**代码修改步骤**

1. 使用`view_file_structure`或`read_file`了解实现
2. 确定修改内容
3. 优先用`find_methods`（类方法）/`find_functions`（全局函数）结合`read_lines(path, startLine, endLine[, encoding])`获取精确上下文（注意，read_lines返回字符串列表，使用`to_string`转成字符串）
4. 多行用`apply_diff`（unified diff格式）；单行用`replace_in_file`或`regex_replace_in_file`（注意，`string_replace`或`regex_replace`是字符串替换，不用于文件）
5. 修改后重新阅读确认
6. 多行替换时建议exactMatch参数为false（默认值，apply_diff、replace_in_file等，此时空白字符不要求精确匹配，可缓解空格、tab、回车换行差异）

**代码语法分析API**

基于语法树精确分析，返回格式化文本。通用签名：`api(filePath, language, [nameRegexPattern])`，带`_in_code`后缀版本签名：`api(code, language, [nameRegexPattern], [fileName])`。

| 类别 | API | 说明 |
|------|-----|------|
| 文件概览 | `view_file_structure`, `view_code_structure` | 查看整体结构 |
| 函数查找 | `find_functions`[`_in_code`], `find_function`[`_in_code`] | 查找所有/指定函数 |
| 类型查找 | `find_types`[`_in_code`], `find_type`[`_in_code`] | 查找所有/指定类型（类/接口/结构体） |
| 变量查找 | `find_variables`, `find_variable`, `find_global_variables`, `find_parameters` | 及对应`_in_code`版本 |
| 类成员 | `find_class_members(filePath, lang, classPattern)` | 查找类所有成员 |
| 类成员细分 | `find_fields`, `find_properties`, `find_methods`, `find_constructors`, `find_events` | 签名：`(filePath, lang, classPattern, [memberPattern])`，events仅C# |
| 接口/结构/枚举 | `find_interfaces`, `find_structs`, `find_enums` | 标准签名 |
| 通用AST | `find_nodes`[`_in_code`], `find_node`[`_in_code`] | 支持html/css/json/toml等所有语言 |

支持语言：C, Cpp, Javascript, CSharp, TypeScript, TSX, Bash, Python, Rust, Go, Java, Swift, PHP, Ruby, Scala, Haskell, Julia, OCaml, Agda, HTML, CSS, JSON, TOML（大小写不敏感，未知名自动转小写尝试加载）。

使用场景：需要理解代码结构、查找定义、分析依赖时，优先使用这些API而非字符串搜索。
